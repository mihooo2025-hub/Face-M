# Facebook Sports News → WordPress Drafts

مشروع Python يعمل عبر GitHub Actions كل ساعة. يجلب المنشورات من مصادر فيسبوك المحددة، يحتفظ فقط بالمنشورات الواقعة ضمن آخر 6 ساعات، يتأكد من وجود نص لا يقل عن 90 كلمة وصورة بارزة، ثم يعيد صياغة النص عبر Gemini ويضع الناتج في ووردبريس كمسودة.

## النماذج

النموذج الأساسي: `gemini-3.6-flash`

النموذج الاحتياطي: `gemini-3.5-flash-lite`

يتم تجربة المفتاح الأساسي أولًا، وعند فشل طلب إعادة الصياغة ينتقل الطلب إلى المفتاح الاحتياطي. يعتمد المشروع على مفتاحين منفصلين حتى لا تتوقف الدورة كاملة عند فشل أحدهما.

## المصادر

المصادر موجودة في `config.py` داخل `FACEBOOK_SOURCES`. لا حاجة إلى تعديلها عند تشغيل المشروع بهذه القائمة نفسها.

هناك مساران للجلب:

1. إذا وُضع `FACEBOOK_ACCESS_TOKEN` يستخدم المشروع Graph API لمحاولة قراءة منشورات المصدر.
2. عند عدم توفر المفتاح أو فشل المسار الرسمي، يحاول قراءة الصفحة العامة مباشرة. فيسبوك قد يعرض صفحة تسجيل دخول أو تحقق أو يغيّر بنية HTML؛ عندها يتم تجاهل المصدر في تلك الدورة بدل توقف بقية المصادر.

> ملاحظة: أسماء `profile.php?id=...` قد تشير إلى صفحات أو ملفات شخصية. المسار الرسمي في Meta لا يضمن الوصول إلى منشورات الملفات الشخصية بالطريقة نفسها التي يتيح بها منشورات الصفحات. لذلك لا توجد طريقة صحيحة لادعاء أن كل هذه الروابط ستعطي منشورات عبر Graph API دون صلاحيات مناسبة من Meta.

## قواعد المقال

القواعد التي أعطيتها محفوظة حرفيًا في:

`rules_ar.md`

الكود يقرأ الملف في كل دورة، لذلك يمكن تعديل قواعد الصياغة مستقبلًا دون تغيير `content_ai.py`.

## ووردبريس

المشروع يبحث عن تصنيف `مقالات وتحليلات` فقط، ويضيفه دائمًا.

ثم يبحث عن تصنيف النادي من القائمة المحددة مسبقًا فقط إذا وجد اسم النادي/أحد أسمائه البديلة في النص الأصلي.

المشروع لا ينشئ أي تصنيف جديد.

يتم رفع صورة المصدر إلى مكتبة ووردبريس ثم إنشاء المقال بالحالة `draft` ووضع الصورة كصورة بارزة.

إذا فشلت صورة المقال فلا يتم إنشاء المسودة.

## منع التكرار وإعادة المحاولة

الحالة محفوظة في `data/state.json` وتُرفع تلقائيًا إلى المستودع بعد كل دورة.

يتم منع التكرار باستخدام رابط المنشور وبصمة النص، مع فحص تشابه للنصوص الناجحة.

أما فشل المعالجة المؤقتة، فيتم تجربته مرتين داخل الدورة نفسها. إذا استمر الفشل، ينتقل المنشور إلى `retry_pending` ويُعاد في الدورات التالية. يستمر ذلك حتى 6 دورات إعادة لاحقة، ثم يتحول إلى `failed_permanent`.

الأسباب غير المؤقتة مثل أقل من 90 كلمة أو عدم وجود صورة يتم تجاهلها مباشرة، لأنها لن تتحسن بإعادة المحاولة.

## الفواصل الزمنية

هناك 10 ثوانٍ فاصلة بين طلبات إعادة الصياغة.

وهناك 3 ثوانٍ بعد إنشاء كل مسودة قبل الانتقال إلى النشرة التالية.

## أسرار GitHub المطلوبة

ضعها في:

`Settings → Secrets and variables → Actions → New repository secret`

الأسماء المطلوبة:

```text
WP_SITE_URL
WP_USERNAME
WP_APP_PASSWORD
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
GEMINI_API_KEY_PRIMARY
GEMINI_API_KEY_FALLBACK
FACEBOOK_ACCESS_TOKEN          # اختياري، لكنه مهم للمسار الرسمي
FACEBOOK_GRAPH_VERSION        # اختياري، الافتراضي في config.py هو v25.0
```

لا تضع أي مفاتيح داخل ملفات المشروع.

## التقرير في تلجرام

بعد انتهاء الدورة يرسل البوت:

- عدد الأخبار المفحوصة.
- عدد المسودات التي أُنشئت.
- عدد الفشل/التجاوز.
- عدد الأخبار المؤجلة لإعادة المحاولة.
- عنوان كل مقال جديد.
- رابط المنشور الأصلي في فيسبوك خلف نص `الرابط القديم`.

## تشغيل محلي

```bash
python -m pip install -r requirements.txt
python main.py
```
